Legend Cube shows a Variant (JSON) cell on one line, `{name: ann, tags: [a, b]}`, numbers as written, and its menu's Open JSON shows the document as a tree, with Copy JSON (PLAN §11.20). Explore JSON… on a Variant column (its cells' and its header's menu) reads its first 1,000 values, or every row, through Runs, shows its fields with their kinds and shares, and adds the columns ticked from each field's offers (the value typed, as JSON, keys, counts, lists, contains, the first element's fields, totals) as one Extend. The core gains `getVariantDatabaseProblem`: JSON is read on Snowflake, Databricks, Postgres and DuckDB. A text cell holding a JSON object or array offers Parse as JSON (`fromJson()`), and the DuckDB Sales sample gains a table of orders as JSON documents, with the example Orders from JSON; an example now runs once its Extend is typed. The new node Explode Array gives one row per element of an array in a Variant column, the element as a new column, keeping a row whose array is empty once; its editor finds the arrays in a sample of the column, and Explore JSON's one row per element adds it. It runs on Snowflake, Databricks, Postgres and DuckDB, is saved in the spec, and Import Pure reads it back. A second DuckDB example, Order lines from JSON, explodes the orders' lines. In the Extend and Filter by Expression editors, a Variant input column's chip opens its fields in place, read from its first values just before the step, so no run is needed: a field clicked is written into the expression, and + column adds it as a new Extend column.
