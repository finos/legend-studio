The Definition tab of an ingest definition with materialized views opens on what they do: a Flow | Pure switch, a list of the views down the left, each with its number of steps, then of the definition's other data sets, each with its number of columns, and the picked one on the right. A view's head shows its name, its primary key, the classification of its data and the data sets it reads, with its own Edit in Cube and Lineage; below, its flow, drawn read-only by Legend Cube's definition flow, which loads the first time it shows. A view Cube can't draw says why and shows its own Pure. A data set shows its key, the views that read it, and its columns, read-only, in View SQL's table: those it declares, then, muted, those its write mode adds. The names a view reads and the views that read a data set link to each other. While the flow shows, the header keeps View SQL and Create MatView; Pure is the whole definition's Pure, under the header as it was. A definition without materialized views is unchanged. Everything the tab shows is read from the definition's specification (`IngestDefinitionEditorState.specification`), rebuilt when its content changes; a definition whose content can't be read shows only its Pure, and says so. The lineage dialog names the view whose lineage it shows. `describeDefinitionFlowRefusal` is exported, for hosts of the flow to say why Cube can't draw a definition.

legend-graph: `getIngestWriteModeColumns` gives the columns a write mode of an ingest definition's specification adds, in the order the engine returns them (`LAKE_DIGEST`, `LAKE_IN_ID`, `LAKE_OUT_ID`, then `LAKE_FROM`, `LAKE_THRU`), and `V1_getMilestoningColumnsForWriteMode` gives them in that order too, so an ingest data set's relation type, e.g. in the query builder and Data Cube, lists them in it; `getIngestDatasetWriteMode` gives a data set's write mode, its own else its definition's. `graphManager.getIngestDatasetsReadByRawLambda` gives the ingest data sets a lambda reads, `#I{definition.dataSet}#`, with no engine call. `getRelationColumnTypeLabel` gives a relation column's type with its parameters, e.g. `Varchar(32)`, which the query builder's relation explorer and View SQL's schema now use.
