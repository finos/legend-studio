# Engine grammar roundtrip tests

[`RoundtripGrammar.engine-roundtrip-test.ts`](./RoundtripGrammar.engine-roundtrip-test.ts) runs every file in [`cases/`](./cases) against a running Legend Engine (`http://localhost:6300`, see [AGENTS.md](../../../../../AGENTS.md#running-engine-server)) through four phases:

1. **`PROTOCOL_ROUNDTRIP`** — engine parses the grammar to protocol JSON; Studio builds a graph from it and serializes it back. The result must deep-equal the engine JSON.
2. **`CHECK_HASH`** — the graph's hashes must match the hashes computed from the protocol.
3. **`GRAMMAR_ROUNDTRIP`** — engine composes the Studio-serialized protocol back to grammar (`renderStyle=STANDARD`). The text must be byte-identical to the case file.
4. **`COMPILATION`** — engine compiles the Studio-serialized protocol.

Each case runs twice: with the extension presets loaded, and with only `Core_GraphManagerPreset` (extension elements then pass through Studio as unknown elements).

## Adding a case

- Name the file `<AREA>-<description>.pure` (e.g. `STO_Relational-database-column-types.pure`); the test name is the file name without `.pure`, with `-` replaced by spaces.
- The text must be in the engine's canonical composed form. The quickest way to get there is to post the draft to `/api/pure/v1/grammar/grammarToJson/model`, post the result to `/api/pure/v1/grammar/jsonToGrammar/model?renderStyle=STANDARD`, adopt the composed text, then check `/api/pure/v1/compilation/compile` accepts the JSON.
- Every case must compile, so declare everything you reference and fully qualify paths. Snippets copied from engine roundtrip tests often reference undefined profiles or stores.
- Run one or more cases with `TEST_GROUP=engine-roundtrip yarn jest packages/legend-manual-tests/src/__tests__/roundtrip-grammar -t "<test name regex>"`.
- Some composed text has trailing whitespace (e.g. legacy relational mapping test data); [`.editorconfig`](../../../../../.editorconfig) keeps it in case files, so don't strip it.
- Only add an entry to `EXCLUSIONS` for a known issue listed below, and link the issue.

## Known engine issues

Constructs that cannot be covered because of the engine itself (as of engine `00108b7`).

- **Grammar → JSON → grammar fails:**
  - `in(col, [1, 2, 3])` literal lists in relational operations: the parser double-wraps each element as a `Literal`, which serializes without `_type`.
  - Primitive `PersistenceContext` service parameters (`foo='hello'`) carry `sourceInformation` even when it is not requested.
  - Quoted schema/table names in `Relational` / `Relation` embedded data (`'my schema'.'My Table'`) compose unquoted.
- **Composer output does not reparse identically:**
  - Postprocessors inside an embedded relational connection: indentation ignores the embedding.
  - Service test `keys` with two or more entries: later keys are written at column 0.
  - An empty `UserList` composes as `users: ['']`.
  - Nested embedded mappings inside a relation function embedded mapping are mis-indented.
  - A standalone `BigQueryFunctionDeploymentConfiguration` element is parsed without a name.
  - Strings containing quotes are not escaped in some composers (relational `mapper` values, MemSql `description`, FileGeneration values).
  - Constructs with no composer support: the `Cron` trigger; HostedService `storeModel`, `generateLineage` and `activationConfiguration`.
- **Parsed but dropped:** ServiceStore `description`; FunctionJar `activationConfiguration`.
- **Fails to compile:**
  - A property typed with a quoted element name (`model::'Rating Grade'`).
  - A `PersistenceContext` pointing at a V2-only persistence.
  - `flag=true` as a `PersistenceContext` service parameter (parsed as a connection named `true`).
  - A JSON schema without `location`.
  - DataSpace `mappingProvider` (no compiler extension in the open-source engine).
  - `~src my::fn()` where `fn` returns `Relation<Any>` (needs a typed relation return).
  - More than one assertion in a mapping test.
  - Window ColSpecs with and without `function2` mixed in one `~[...]`.
- **Parser errors:** an `ExecutionEnvironment` mixing flat and nested entries (NPE); ServiceStore HTTP methods other than `GET` / `POST`; stereotypes / tagged values on relation type columns in function signatures; `store` inside a package path in a Deephaven connection.
- **Not available in the open-source engine image:** DataProduct, Ingest, FlatData and `ExternalFormatConnection` grammars; datasource specifications for Athena, Aurora, GlobalAurora, ClickHouse, SqlServer, Sybase, Postgres, Hive, Presto, SparkSQL and MemSQL (those database types still work with a `Static` specification).

### Normalized by the engine composer

These are rewritten on compose, so write the normalized form in cases:

- `INT`, `BOOLEAN`, `ARRAY` column types become `INTEGER`, `BIT`, `OTHER`; `... = false` milestoning flags and `platform: Default;` are dropped.
- Float literals such as `0.0` come back as `0` after the JSON roundtrip; use values like `0.5`.
- An empty DataQuality `keys: []` is omitted; `extends meta::pure::metamodel::type::Any` is omitted; Diagram hide flags set to `false` are omitted.
- `scope(...)` blocks in relational mappings are flattened; `~primaryKey` inside embedded mappings is dropped.
- A join type is not allowed on the first join of a relational property mapping (it is on later joins and on `~filter`).
- Legacy relational `MappingTests` input data lines end with a trailing space.
